# 季度审计 Checklist

> **用途**: 每季度一次的 skill 质量审计标准化流程  
> **审计周期**: 每 3 个月（首次 2026-09，其次 2026-12，以此类推）  
> **审计副本**: 存放于 `AUDIT_REPORT.md`，每次审计写出新版本  
> **版本锚点**: 审计时的最新 HarmonyOS Release 版本

---

## 一、审计前准备（审计日 T-3）

- [ ] 确定审计覆盖的 HarmonyOS API 版本锚点
- [ ] 更新 `tools/sdk-diff/diff_api.py` 的基线到最新 SDK d.ts
- [ ] 运行 `sdk-diff/diff_api.py` 生成变更清单
- [ ] 标记受变更影响的 skill（对照 `skill_map.json`）
- [ ] 审查上次审计的待处理项完成率

## 二、逐 Skill 审查（审计日）

### 2.1 全量 skill 覆盖检查

对每个深度 skill，逐条检查：

- [ ] **API 版本声明**: 所有 "API xx+" / "HarmonyOS x.x 起" 声明与 SDK 变更清单比对
- [ ] **API 方法名**: 抽样 3 个关键 API 名，搜索官方文档或 SDK d.ts 确认存在
- [ ] **Kit 名称**: `@kit.Xxx` 格式与官方 `kit-list.md` 比对
- [ ] **文档 URL**: 抽查 30% 的 URL，`curl -sI` 验证 200 状态码
- [ ] **代码示例**: 至少 1 处关键代码片段逐行比对官方示例
- [ ] **错误码/枚举**: 关键错误码和枚举名搜索官方 API 参考确认
- [ ] **引用完整性**: `references/` 和 `scripts/` 文件均存在
- [ ] **新增 Kit 覆盖**: 上次审计以来官方的 Kit 变更是否已反映

### 2.2 索引 skill 路由检查

- [ ] 总索引 `harmony-index` 的路由表是否与当前 plugin 结构一致
- [ ] 各领域索引 `0-*-index` 的路由表是否涵盖所有现有深度 skill
- [ ] 无因重构/重命名遗留的死亡路由

## 三、行业同步（审计日 +1）

- [ ] 检查 HarmonyOS 官方 release notes（版本概述页 / changelog）
- [ ] 检查 51CTO/CSDN/掘金 等社区近 3 个月的高热度 HarmomyOS 文章
- [ ] 如有重大 SDK 变更（如 API 级别跳跃、Kit 重组），评估是否需要紧急更新

## 四、判定标准

### 通过条件
- P0 问题（虚构 API / 编写规则 / 错误 Kit 名） = 0
- P1 问题（过期 API 声明 / 失效 URL / 缺 kits 字段） ≤ 3
- P2 问题（术语不规范 / 版本号不精确） = 不计入评级

### 评级
| 评级 | P0 | P1 |
|------|----|----|
| A | 0 | 0 |
| B | 0 | 1-3 |
| C | 0 | 4-6 |
| D | ≥1 | / |

### 处理时间线
- P0: 48h 内修复
- P1: 当周修复
- P2: 择机修复

## 五、审计产物

- [ ] `AUDIT_REPORT.md` 更新为新版本（v{N}.0）
- [ ] `CHANGELOG.md` 记录审计版本与关键修复
- [ ] `ROADMAP.md` 进度更新
- [ ] 如有 evals 回归失败，补充 evals 条目
