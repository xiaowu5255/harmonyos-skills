将本次会话中已解决的鸿蒙开发问题蒸馏为标准知识条目,流程:

1. 回顾本会话,提取:报错原文片段(可 grep 的特征)、所属层(依赖/编译/打包/签名/
   安装/运行/端云)、根因链条、已验证的修复步骤、工程的 API 版本与 DevEco 版本。
2. 按 harmony-debugging 技能 `references/common-errors.md` 末尾的"条目贡献规范"
   格式化为 Markdown 条目。
3. 输出该条目,并询问用户希望如何提交:
   a) 直接追加到本地已安装技能的 common-errors.md(个人知识库模式);
   b) 生成一段可直接粘贴到插件仓库 issue 的文本(社区回流模式)。
4. 若本次问题暴露了 SKILL.md 正文的错误或缺失,一并指出建议修改的位置。

注意:只蒸馏"已验证解决"的问题;仍是猜测的内容标注为未验证,不进对照表正文。
